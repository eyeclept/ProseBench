# Analytic hardware cost

This axis estimates the cost of output-token decoding on NVIDIA DGX Spark systems. It does not measure the scored runs on local hardware. The source inputs and the requested study snapshot date are in [hardware.yml](hardware.yml). The [study plan](../../plan.md) supplies model sizes, box counts, and OpenRouter output prices. The five local candidates include Qwen3.6 as the Ornith fallback. MiMo-V2.6-Pro and Mistral Large 4 remain cloud-only and have no Spark comparison row.

For each model, capex per productive hour is `box_count * unit_price / (years * 365 * productive_hours_per_day)`. Power cost per productive hour is `box_count * load_w / 1000 * electricity_usd_kwh`. The sum divided by `decode_tokens_s * 3600`, then multiplied by one million, gives hardware USD per million output tokens. The two duty cycles assume 8 or 24 productive decoding hours per day for three years. The model charges power only during productive decoding. It excludes idle power, cable cost, storage, maintenance, resale value, prompt prefill, and parallel-request throughput. Treat these omissions as limits, not measured savings.

NVIDIA documents [128 GB per unit and 273 GB/s memory bandwidth](https://docs.nvidia.com/dgx/dgx-spark/hardware.html). It documents [QSFP Ethernet cabling through ConnectX-7](https://docs.nvidia.com/dgx/dgx-spark/spark-clustering.html). Two boxes have 256 GB in aggregate across their separate memory pools, not a single 256 GB address space. NVIDIA's [Founders Edition price notice](https://forums.developer.nvidia.com/t/2-23-2026-price-change-announcement/361713) gives $4,699 per unit. [ServeTheHome measured 60-90 W during LLM inference](https://www.servethehome.com/nvidia-dgx-spark-review-the-gb10-machine-is-so-freaking-cool/4/). This model uses 90 W per unit, not the 240 W supply rating. [EIA Table 5.6.A](https://www.eia.gov/electricity/monthly/epm_table_grapher.php?t=epmt_5_6_a) reports 18.31 cents/kWh for the July 2026 U.S. residential average.

The throughput entries cite single-stream model recipes or NVIDIA forum benchmarks. Their input length, output type, and speculative decoding differ. Do not treat the resulting model rankings as controlled throughput measurements. The plan's total parameters, active parameters, and required box count appear as separate columns. Qwen3.8 Flash also has a separate 51B n-gram embedding table. It is not added to active parameters.

Run `PYTHONPATH=. /home/eyeclept/Documents/School/DataMining-645/Project/.venv/bin/python -m bench.analysis.cost_model` from the repository root. The command prints a Markdown table and writes `bench/analysis/cost_comparison.csv`. Supply `--runs-csv scores/runs.csv` to include scored output-token totals and estimated study hardware cost. Routed Ornith rows count under Qwen3.6. `usage_reasoning` is reported separately and is not added to `usage_output`, since the scorer already reports both fields. Study cost uses output tokens only, not actual elapsed wall time or input usage. An absent run stays blank, not zero.

For a `t1_failure` route, the scorer sums usage across failed Ornith attempts and the Qwen3.6 fallback. The run CSV cannot split that usage by endpoint. The Qwen3.6 study-cost figure for such a run is an allocation estimate, not an endpoint measurement.
